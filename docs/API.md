# API командного центра

Панель — обычный веб-клиент поверх этого API. Всё, что она умеет, доступно
и снаружи: подключить свой дашборд, дёрнуть паузу из скрипта, залить лиды
из внешнего источника.

База: `http://localhost:8000` (порт задан в `run.sh`).

Аутентификации нет — сервер рассчитан на локальный запуск. Прежде чем выставлять
его наружу, закройте доступ обратным прокси: `/api/control` останавливает всех
агентов, а `/api/approvals/{id}/resolve` подтверждает коммерческие предложения.

---

## REST

### `GET /` — панель

Отдаёт `web/index.html`. Статика панели смонтирована на `/web`.

### `GET /api/state` — полный снимок

Одним ответом всё, что рисует панель. Панель берёт его при загрузке, дальше
живёт на WebSocket.

```json
{
  "company": "NEUROCORP",
  "demo": true,
  "paused": false,
  "workforce": { "...": "состояние агентов по узлам" },
  "pipeline":  { "NEW": 4, "CONTACTED": 7, "...": 0 },
  "metrics":   { "...": "счётчики воронки" },
  "approvals": [ { "id": 12, "kind": "project_kp", "title": "..." } ],
  "contacts":  [ { "id": 1, "name": "...", "stage": "ENGAGED" } ],
  "feed":      [ { "type": "log", "ts": 1785000000.0, "data": {} } ],
  "stages":    ["NEW", "CONTACTED", "ENGAGED", "..."],
  "policy":    { "...": "политика одобрений из core/config.py" }
}
```

Контактов отдаётся до 60, событий ленты — до 60.

### `GET /api/contact/{id}` — карточка клиента

```json
{ "contact": { "id": 1, "name": "..." }, "interactions": [ { "...": "..." } ] }
```

`interactions` — вся переписка и действия по контакту в хронологическом порядке.

### `GET /api/inspect/{node}` — что происходит внутри узла

То же, что клик по узлу на схеме. Ответ зависит от узла:

| `node` | Что в ответе |
|---|---|
| `m1`, `m2` | `dialogues` — диалоги менеджера 1 или 2 на стадиях `NEW` и `CONTACTED` |
| `rp` | `dialogues` — стадии `RP_REVIEW` и `APPROVAL` |
| `you` | `approvals` — очередь man-in-the-middle |
| `analyst`, `developer`, `consultant`, `tester`, `acceptor` | `board` — задачи узла, `reports` — его отчёты |
| `done` | `dialogues` — сделки в `WON` |
| `clients` | `contacts` — до 80 контактов |

Неизвестный узел — `404` и `{"error": "unknown node"}`.

### `POST /api/approvals/{id}/resolve` — решение оператора

Ключевая ручка man-in-the-middle: пока по карточке нет решения, работа стоит.

```json
{ "decision": "approved", "note": "срок сдвинуть на неделю", "override": { "price": 180000 } }
```

| Поле | Обязательно | Смысл |
|---|---|---|
| `decision` | нет, по умолчанию `approved` | `approved` — запустить в производство, `rejected` — отклонить |
| `note` | нет | комментарий человека, ложится в историю |
| `override` | нет | правки payload перед запуском: значения перекрывают предложенные агентом |

Ответ `{"ok": true}`. Если карточки нет или она уже решена — `{"ok": false, "error": "not_pending"}`
(с кодом `200`: повторное нажатие в панели не должно выглядеть как сбой).

Отклонение переводит контакт в `LOST` и пишет отказ в историю взаимодействий.

### `POST /api/leads` — добавить лид

```json
{ "name": "Иван Петров", "company": "ООО Ромашка", "role": "директор",
  "email": "i@example.com", "phone": "+7...", "telegram": "@ivan",
  "lang": "ru", "source": "Manual" }
```

Все поля кроме `name` необязательны; без `name` контакт заводится как
«Без имени». `lang` по умолчанию `ru`, `source` — `Manual`.

Ответ: `{"ok": true, "id": 42}`.

### `POST /api/control` — пауза и возобновление

```json
{ "action": "pause" }
```

`action` — `pause` или `resume`. Ответ: `{"ok": true, "paused": true}`.
Неизвестное действие ничего не меняет и возвращает текущее состояние.

Пауза останавливает оркестратор: агенты не берут новые задачи. Уже запущенные
шаги досчитываются.

## WebSocket

### `GET /ws`

Сразу после подключения приходит снимок:

```json
{ "type": "snapshot", "data": { "...": "то же, что GET /api/state" } }
```

Дальше — поток событий. Общая форма:

```json
{ "type": "<тип>", "ts": 1785000000.0, "data": { "...": "..." } }
```

| `type` | `data` | Когда |
|---|---|---|
| `log` | `line`, `level` (`info` / `good` / `warn` / `bad`) | строка в терминал панели |
| `flow` | `src`, `dst`, `color`, `label`, `contact_id`, `name` | анимация передачи работы между узлами |
| `approval_resolved` | `approval_id`, `decision` | оператор принял решение |

`src` и `dst` — ключи узлов схемы либо `client`.

Последние 200 событий держатся в буфере, `GET /api/state` отдаёт из него
последние 60 — новый клиент видит контекст, а не пустой экран.

Медленный клиент не тормозит систему: при переполнении очереди (500 событий)
самое старое выбрасывается. Разрыв соединения обрабатывается молча,
подписка снимается.

## Типовые сценарии

**Внешний источник лидов.** Раз в час выгружайте новых клиентов и лейте
`POST /api/leads` — дальше конвейер сам.

```bash
curl -s -X POST localhost:8000/api/leads \
  -H 'Content-Type: application/json' \
  -d '{"name":"Иван Петров","company":"ООО Ромашка","source":"Выставка"}'
```

**Стоп-кран.** Останавливает исходящие, пока разбираетесь:

```bash
curl -s -X POST localhost:8000/api/control \
  -H 'Content-Type: application/json' -d '{"action":"pause"}'
```

**Одобрение не из панели** — например, из телеграм-бота: слушайте `/ws`,
на событии с новой карточкой шлите себе сообщение, а по кнопке дёргайте
`POST /api/approvals/{id}/resolve`.

## Границы

- Нет аутентификации и нет CORS-заголовков: браузерный клиент с другого
  origin работать не будет, `curl` и серверные клиенты — да.
- Нет пагинации: списки ограничены сверху (60 контактов в снимке, 80 в
  `inspect/clients`, 60 событий ленты).
- Нет версионирования. Формат событий и полей снимка может меняться вместе
  с панелью — она и API правятся одним коммитом.
